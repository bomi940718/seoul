# WorkReport — 설치와 사용 안내

이 폴더를 통째로 `C:\Tools\WorkReport` 로 복사하면 됩니다. **두 PC 모두 같은 방법으로 설치**하고,
설정만 각자 PC에서 따로 잡습니다.

---

## 1. 설치 (PC마다 한 번)

### ① Excel이 32비트인지 64비트인지 확인

Excel에서 **파일 → 계정 → Excel 정보** 를 열면 맨 위 제목줄 끝에 `32비트` 또는 `64비트` 라고 나옵니다.

| Excel | 설치할 파일 |
|---|---|
| 32비트 | `dist\WorkReport-AddIn.xll` |
| 64비트 | `dist\WorkReport-AddIn64.xll` |

> 이 PC(백보미 님)의 Excel은 **32비트**로 확인됐습니다 → `WorkReport-AddIn.xll` 을 쓰시면 됩니다.

### ② 차단 해제 (인터넷을 거쳐 받은 파일일 때만)

xll 파일을 **오른쪽 클릭 → 속성** → 아래쪽에 `보안: 이 파일은 다른 컴퓨터에서...` 문구가 있으면
**[차단 해제]** 체크 후 확인. 문구가 없으면 그냥 넘어가세요.

이 과정을 건너뛰면 Excel이 애드인을 조용히 차단해서 리본 탭이 나타나지 않습니다.

### ③ Excel에 등록

1. Excel 실행 → **파일 → 옵션 → 추가 기능**
2. 아래쪽 **관리:** 목록에서 **Excel 추가 기능** 선택 → **[이동]**
3. **[찾아보기]** → 위에서 고른 xll 선택 → **[확인]**
4. 목록에 `WorkReport-AddIn` 이 체크된 상태로 보이면 완료

리본에 **[워크리포트]** 탭이 생깁니다. 다음부터는 Excel을 켤 때 자동으로 로드됩니다.

## 2. 첫 설정 (PC마다 한 번)

**[워크리포트] 탭 → [설정]** 에서 아래를 채웁니다.

| 항목 | 내용 | 두 PC 관계 |
|---|---|---|
| 내 일지 xlsx | 본인이 기록하는 일지 파일 | **각자 다름** |
| 내 작성자명 | 리포트에 표시될 본인 이름 | **각자 다름** |
| 협업자 일지 xlsx | 상대방 일지 파일 (NAS 경로) | 서로 반대로 |
| 협업자 작성자명 | 상대방 이름 | 서로 반대로 |
| 공유설정 폴더 | `projects.json` 이 놓일 NAS 폴더 | **두 PC 동일** |
| 출력 루트 폴더 | HTML 리포트가 쌓일 NAS 폴더 | **두 PC 동일** |
| 대상 시트명 | 비우면 올해 연도 시트를 자동 사용 | 보통 비움 |
| 저장할 때 자동 갱신 | 켜면 일지 저장 시 조용히 리포트 갱신 | 취향껏 |

그다음 **[프로젝트 관리]** 에서 프로젝트를 등록합니다.
창을 열면 일지를 훑어서 **아직 등록되지 않은 프로젝트 넘버**를 오른쪽에 보여주므로,
항목을 더블클릭하면 넘버·이름이 채워진 행이 바로 추가됩니다. 그룹과 상태만 정리하고 저장하세요.

- **넘버**: 일지 I열 값과 맞아야 합니다 (대소문자·공백·줄바꿈 차이는 알아서 같게 봅니다)
- **그룹**: 대시보드 상단 탭 이름. **비워두면 자동으로 정해집니다** (아래 참고)
- **같은 프로젝트 넘버**: 같은 프로젝트인데 다른 이름으로도 적힌 경우 여기에 넣습니다 (쉼표로 여러 개)
- **상태**: 계획 / 진행 / 완료 — 완료는 대시보드에서 기본으로 숨겨집니다
- **활성** 해제: 기록은 남기되 리포트에서 제외

### 그룹 자동 배정

창 위쪽 **그룹 이름** 칸에 쓸 그룹을 쉼표로 적어둡니다. 예:

```
ARCHITECTURE, INTERIOR, EDUCATION, BRANDING, MANAGEMENT, PLANNING
```

이렇게 해두면 프로젝트의 **그룹 칸을 비워둬도** 일지의 H·I 열에서 이 이름을 찾아 알아서 분류합니다.
`BRANDING-1` → BRANDING, `General Management` → MANAGEMENT, `Planning project` → PLANNING 처럼
일부만 일치해도 잡히고, 대소문자는 구분하지 않습니다. 앞에 적은 이름이 우선입니다.

앞으로 새 프로젝트를 등록할 때도 그룹을 따로 입력할 필요가 없습니다.
특정 프로젝트만 다르게 묶고 싶으면 그 행의 그룹 칸에 직접 적으면 그 값이 이깁니다.
아무것도 걸리지 않으면 `ETC`로 갑니다.

### H·I 열이 뒤바뀐 기록 합치기

같은 프로젝트인데 어떤 날은 H열에, 어떤 날은 I열에 프로젝트 이름을 적은 경우
리포트가 두 개로 갈라집니다. **[H·I 뒤바뀐 쌍 … 합치기]** 버튼을 누르면
그런 쌍을 찾아 한 프로젝트로 묶어줍니다 (기록이 많은 쪽이 대표가 되고 반대쪽은 별칭으로 들어갑니다).

무엇을 합칠지 먼저 보여주고 확인을 받으며, **엑셀 일지는 전혀 바뀌지 않습니다.**
한 넘버를 서로 다른 두 프로젝트가 함께 쓰고 있으면 잘못 합칠 위험이 있어 건너뛰고 알려줍니다.

## 3. 매일 쓰는 법

1. 평소처럼 일지 xlsx에 기록하고 저장합니다.
2. **[워크리포트] 탭 → [리포트 갱신]** 클릭
   - 열려 있는 문서를 저장하고, 두 사람 일지를 합쳐 HTML을 다시 만들어 NAS에 복사합니다
   - 결과 창에 프로젝트별로 본인/협업자 기록 건수가 나옵니다
3. **[대시보드 열기]** 로 확인하거나, NAS 폴더의 `index.html` 을 더블클릭합니다.

설정에서 자동 갱신을 켜두면 2번은 저장할 때 알아서 돌아갑니다 (결과 창은 뜨지 않습니다).

### 리본 버튼

| 버튼 | 하는 일 |
|---|---|
| 리포트 갱신 | 일지 병합 → HTML 재생성 → NAS 복사 |
| 대시보드 열기 | `index.html` 을 브라우저로 |
| 프로젝트 관리 | 프로젝트 목록 편집, 미등록 넘버 확인 |
| 설정 | 경로·이름·자동 갱신 설정 |
| 로그 열기 | 오늘 실행 기록 (문제 확인용) |

---

## 4. 알아두면 좋은 것

- 일지 xlsx는 **읽기만** 합니다. 서식이나 내용을 건드리지 않습니다.
- HTML은 매번 **전체를 다시 만듭니다**. 손으로 고쳐도 다음 갱신 때 사라집니다.
  나중에 쓴 내용은 다음 갱신 때 그대로 추가되고, **중복되지 않습니다**.
- 프로젝트 이름이나 넘버를 바꾸면 파일 이름도 바뀌는데, **옛 이름의 파일은 자동으로 정리됩니다.**
  이때 지우는 대상은 이 도구가 만든 파일뿐이라, 같은 폴더에 두신 다른 파일은 건드리지 않습니다.
- 리포트는 파일 하나에 모든 게 들어 있어 **인터넷 없이** 열립니다. NAS에서 바로 더블클릭하세요.
- 프로젝트 상태를 카드에서 바꾸면 그 PC에만 저장됩니다. 모두에게 반영하려면 **[프로젝트 관리]** 에서 바꾸세요.
- NAS가 연결되지 않아도 갱신은 실패하지 않습니다. 로컬 임시폴더에 만들고 그 경로를 알려줍니다.

## 5. 문제가 생기면

먼저 **[로그 열기]** 로 오늘 기록을 확인하세요 (`%LOCALAPPDATA%\WorkReport\logs\`).

| 증상 | 확인할 것 |
|---|---|
| [워크리포트] 탭이 없음 | 위 ①②③ — 특히 Excel 비트와 차단 해제 |
| "설정되지 않았습니다" 안내 | [설정]에서 공유설정 폴더·내 일지 경로 |
| "시트를 찾을 수 없습니다" | [설정]의 **대상 시트명**. 일지의 실제 시트 이름과 정확히 같아야 합니다.<br>보통은 **비워두면** 올해 연도 시트를 자동으로 씁니다 |
| 레코드 0건 | 위와 같은 시트명 문제이거나, 일지 경로가 잘못된 경우 |
| 특정 프로젝트가 리포트에 없음 | [프로젝트 관리]에서 등록됐는지, 활성인지 |
| 상대 기록이 안 보임 | 협업자 일지 경로, NAS 연결 상태 (로그에 경고가 남습니다) |
| NAS 복사 실패 경고 | NAS 접근 권한. 로컬 결과 경로가 결과 창에 표시됩니다 |

## 폴더 구성

| 경로 | 내용 |
|---|---|
| `dist\` | **설치용 xll** (32비트 / 64비트) |

| `docs\DEV-NOTES.md` | 실측 스펙·설계 확정 기록 |

## (선택) 소스에서 직접 빌드

.NET 8 SDK 필요. Excel에 애드인이 로드된 상태면 xll이 잠겨 패킹이 실패하니 Excel을 닫고 실행하세요.

```
cd C:\Tools\WorkReport
dotnet test
dotnet build src\WorkReport.AddIn\WorkReport.AddIn.csproj -c Release
```

결과물은 `src\WorkReport.AddIn\bin\Release\net48\publish\` 에 생기며, 이를 `dist\` 로 복사하면 됩니다.
