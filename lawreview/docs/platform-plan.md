## 2. 남들과 겹치지 않는 자리

| 유형 | 이미 있는 것 | 우리는 |
|---|---|---|
| 질의응답형 | ALRIS(건축공간연구원, 무료), 아키로, 건축규정 코파일럿, 로키텍트 | 만들지 않는다 — 무료 공공 서비스가 있다 |
| 도면 입력형 | 스페이스워크 PlanReviewer, 희림 사내 시스템 | 우리 규모가 아니다 |
| 대지·건물 분석형 | **SPACEVISION**, 랜드북, 빌드잇, 밸류맵 | 같은 시장 — 아래 4가지로 다르게 간다 |

SPACEVISION: 무료·가입 없이 대지분석 / 건물분석 / 비용계산기 / 법규체크(16개 용도·49개 세부용도,
"400+ 항목", 변경 전·후 "용도 비교") 제공. 이용 사례에 부동산 중개인 포함. 법규 기준일 2025년 2월이라는 면책 문구.

**우리 자리**
1. **적게 보여준다** — 코드로 YES/NO가 확실한 것만. 나머지는 "건축사 확인 필요" 한 줄로 묶어 상담으로 보낸다.
2. **오늘 기준 법령** — 법제처 현행 원문과 조례를 법 위계(기초 조례 → 광역 조례 → 모법)로. 기준일이 고정된 서비스와 다른 점.
3. **사람이 붙는다** — 결과 바로 아래에 지역 건축사(미유헌) 연락처. 무료 도구는 입구이고, 매출은 사전검토·설계·감리에서 난다.
4. **중개사 전용 입구** — 중개사마다 다른 QR과 기록. 어느 중개사가 어떤 매물을 물었는지가 곧 영업 자료.

## 3. 입구별 설계

### 3-1. 중개사 — 용도변경 바로 확인 (명함 QR)

- **입력**: 주소(+동·층·호) / 들어올 업종(목록에서 고름. 예: 카페, 음식점, 학원, 병원·의원, 헬스장·필라테스,
  미용실, 사무실, 스터디카페·PC방, 노래연습장 — 처음 10~15개) / 면적(건축물대장에서 자동, 고칠 수 있음)
- **자동 조회**: 건축물대장(현재 용도·층별 면적·사용승인일), 용도지역·지구(VWorld)
- **결과** — 사용자의 용도변경 가이드 엑셀(A·B시트, `usechange-excel-analysis.md`)을 줄인 것:

| # | 질문 | 근거 |
|---|---|---|
| 1 | 이 동네(용도지역)에서 이 업종이 되나 | 국토계획법 시행령 제71조·별표 + 도시계획조례 |
| 2 | 절차: 허가 / 신고 / 대장 기재변경 / 그대로 사용 | 건축법 제19조, 시행령 제14조(9개 시설군) |
| 3 | 주차를 더 만들어야 하나 | 주차장법 시행령 제6조 — 차이분, 면제(사용승인 5년 경과 + 연면적 1천㎡ 미만 등) |
| 4 | 위반건축물인가 | 건축물대장 (API로 나오는지 키 받은 뒤 확인) |
| 5 | 건축사 설계가 필수인가 | 허가 대상 + 바닥면적 합계 500㎡ 이상 |
| 6 | 따로 챙길 것 | 정화조 용량, 다중이용업소 소방 완비증명, 장애인 편의시설 — 해당하면 "확인 필요" |

- 판정할 수 없으면 **"확인 필요"**. YES로 우기지 않는다(검토 품질 원칙 5).
- 맨 아래: **정식 사전검토 받기** (전화 / 카카오톡 채널 / 문의 폼 — 결정 필요)
- **중개사 구분**: QR마다 코드(예: `/b/A01`). 첫 방문에 브라우저에 저장한다. 기록은 코드·시각·주소·업종·결과뿐이다.
  손님 개인정보는 받지 않는다. 상담 신청 때만 동의를 받고 연락처를 받는다(개인정보처리방침 페이지 필요).
- **지역**: 처음엔 **안양시만**(명함 돌릴 지역). 조례 해석을 지역 단위로 검증하고 넓힌다.
- **나중에**: 결과 카톡 공유, 대략 비용(허가 수수료·하수도 원인자부담금), 중개사별 월간 조회 리포트.
- 보류 4번(건축사용 용도변경 검토기 — 엑셀 가이드 전체 이식: 변경 전·후 2열 비교, 오수량, 수수료)은 **보류 유지**.
  중개사 입구는 그중 판정 부분(시설군·용도지역·주차 차이·대장)만 먼저 만들고, 4번을 할 때 그대로 재사용한다.

### 3-2. 건축주 — YES/NO (SNS)

- **시작 질문 셋**: 빈 땅에 짓기 / 있는 건물 늘리기·고치기 / 용도 바꾸기(중개사와 같은 엔진)
- **카드** (각각 YES / NO / 확인 필요):

| 시작 | 카드 |
|---|---|
| 빈 땅 | 원하는 건물(단독주택·다가구·상가주택·근생 등)이 되나 / 최대 건축면적·연면적(대략 층수) / 특별 규제(지구단위계획·개발제한구역 등)가 있나 |
| 있는 건물 | 증축 여유가 있나(법정 용적률 − 대장상 현재 용적률 → 약 n㎡) / 위반건축물인가 / 원하는 용도로 바꿀 수 있나 |

- 법규 목록과 조문은 보여주지 않는다(SPACEVISION과 반대). 근거는 "자세히" 접기 안에만 둔다.
- SNS 연결: 인스타(인스타툰·D+Tail) → 프로필 링크 → 카드 → 상담. 결과 카드는 이미지로 저장해 공유할 수 있게.

### 3-3. 건축사 — 전체 업무 (지금 exe 확장)

- **업무 유형 9종** (건축법 정의 그대로):

| 지금 있음 | 추가 |
|---|---|
| 신축 · 증축 · 리모델링 · 용도변경 | 개축 · 재축 · 이전(제2조 제1항 제8호), 대수선(제9호), 실내건축 = 인테리어(제52조의2) |

- **흐름**: 대지 조회 → 건축물대장 → **서류 받기**(토지이용계획 열람본 PDF · 대장 조회 요약) → 법규검토서 DOCX
  → **땅튀기기**(지적 경계 + 건폐율·대지 안의 공지·정북일조·높이 → 최대 볼륨 솔리드 박스) → **Revit 매스**(보유한 Revit MCP 애드인)
- cadastral-mcp(지적 DXF)와의 역할 분담, 입력·출력 형식은 CAD 논의 때 정한다(보류 3번).

## 4. 기술 구조

```
LawReview.Core   엔진 — 하나
  ├ 조회  VWorld · 토지이음 · 건축HUB 건축물대장(새로) · 법제처
  ├ 판정  법 위계(조례 → 모법) · 용도 분류·시설군(새로) · 용도지역 허용(새로) · 용도변경 절차(새로)
  ├ 계산  건폐율·용적률·주차 · 매스(나중)
  └ 출력  DOCX · PDF · DXF/Revit(나중)
LawReview.Web    화면 + API
  ├ /pro    건축사 화면 — 지금 화면. 데스크톱 exe 안에서만
  ├ /agent  중개사 화면 — 공개
  └ /owner  건축주 화면 — 공개
LawReview.App    데스크톱 셸 — 건축사용 exe (지금 그대로)
```

- 공개 서버는 `/agent`·`/owner`와 그 API만 연다. **설정·키 API(`/api/settings`)와 건축사 화면은 공개 서버에서 끈다.**
- 공개 쪽은 **Claude API를 부르지 않는다**(호출당 과금 + 정확도). 코드로 판정되는 것만 보여준다.
- 공개 쪽은 몇 초 안에 답해야 한다. 지금 기본 검토는 처음 20초 안팎이므로 필요한 조회만 하고 결과를 캐시한다.
- **키 원칙**: 건축사 exe는 지금처럼 PC별 키. 공개 서버는 사무소 키를 서버에만 둔다(브라우저로 내려보내지 않는다).
  VWorld 키는 서비스 URL에 묶이므로 서버 도메인으로 따로 받는다.
- **도메인을 먼저 산다.** QR이 도메인을 가리키면 서버를 옮겨도 명함을 다시 찍지 않아도 된다.
  서버는 소형 클라우드(추천) 또는 사무실 PC(무료지만 정전·회선 문제가 곧 서비스 중단).

## 5. 순서 — 돈이 되는 순서

| 단계 | 내용 | 먼저 쓰는 곳 | 막혀 있는 것 |
|---|---|---|---|
| 0 (지금) | 공공데이터포털 키 신청 · 개발 틀 정리(6장) · 이 계획 확정 | — | 사용자 결정 |
| 1 | 건축물대장 연결 + **서류 받기(2번)** + 용도 분류·시설군·용도지역 허용 판정 | 건축사 exe에서 먼저 검증 | 키 |
| 2 | 중개사 용도변경 웹 + 도메인·서버 + QR | 중개사 | 서버 결정, 개설신고(문의를 계약으로 바꾸려면) |
| 3 | 건축주 YES/NO 웹 + 결과 이미지 | SNS | 2단계 서버 |
| 4 | 건축사 확장: 업무 유형 9종, 땅튀기기·매스, Revit | 건축사 | 보류 3번(CAD 논의) |
| 수시 | 법규검토서 수정(보류 1번) — 내용이 오는 대로 끼워 넣는다 | 건축사 | 내용 |

- 1단계는 세 입구 모두의 바닥이다. 그래서 "2번(서류 받기)부터"와 순서가 겹친다.
- 중개사 입구가 범위가 가장 좁고(용도변경 하나) 명함 영업과 바로 이어진다. 다른 대화의 결론
  ("업무 시간 개발은 돈 받는 상품에 붙는 것만", 용도변경 사전검토 → 중개사 20곳)과 같은 방향이다.
- 땅튀기기·Revit(4단계)은 작업량이 가장 크다. 규모검토는 설계 수주에 쓰이는 도구라 버리지 않되, 앞 단계 뒤에 둔다.

## 7. 사용자가 정할 것

1. 순서(5장): 중개사 → 건축주 → 건축사 확장
2. 공개 서버: 클라우드 / 사무실 PC, 그리고 도메인 이름
3. 결과 뒤 연결 수단: 전화 / 카카오톡 채널 / 문의 폼
4. 중개사용 업종 목록 첫 10~15개 (실무에서 자주 받는 것)
5. 정식 사전검토: 무료 상담 / 정해진 가격의 유료 상품

**보류 유지**: 1번 법규검토서 수정 내용 · 3번 CAD(입력·출력·cadastral-mcp 역할) · 4번 건축사용 용도변경 검토기(오수량 원단위 최신 자료 포함)
